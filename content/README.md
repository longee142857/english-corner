# English Corner content

Corpus files live here. Schemas in `content/schemas/` are the contract. `scripts/validate-content.mjs` and `scripts/build-index.mjs` enforce it with Node only — no npm install.

The real corpus is not generated by this pipeline. Add JSON under the paths below, then validate and rebuild the index.

## Layout

| Path | Container | Schema |
| --- | --- | --- |
| `content/curriculum/topics.json` | array of topics | `topic.schema.json` |
| `content/dialogues/*.json` | array of dialogues | `dialogue.schema.json` |
| `content/vocabulary/packs/*.json` | one pack object per file | `vocab-pack.schema.json` |
| `content/reading/*.json` | array of readings | `reading.schema.json` |
| `content/listening/*.json` | array of listenings | `listening.schema.json` |
| `content/debates/motions.json` | array of motions | `debate.schema.json` |
| `content/index.json` | generated light catalog | `index.schema.json` |

`content/fixtures/` mirrors that layout for a self-test. Do not put real lessons there, and do not copy fixture files into the corpus folders.

`content/schemas/` is not scanned as content. `manifest.json` in an area is a catalog, not a lesson file.

Split large sets across files (for example one dialogue file per theme). The index builder parses one file at a time and drops passage, script, and turn text after checking them.

## Closed vocabularies

Levels: `A1` `A2` `B1` `B2` `C1`

Domains: `daily-life` `campus` `travel` `academic` `career` `culture` `exam` `interview` `debate`

Vocab types: `word` `phrase` `collocation` `idiom`

Piece kinds: `reading` `listening` `debate`

Themes are free strings. Prefer lowercase kebab-case slugs such as `greetings` or `job-interview`. Part of speech (`pos`) is a free string (`noun`, `verb`, `adjective`, `adverb`, `phrase`, …).

Whitespace-only strings are rejected. Extra fields are allowed on source objects and are omitted from the index.

## Id rules

Ids are lowercase kebab-case and unique across the whole corpus (topics, packs, vocab entries, dialogues, readings, listenings, and motions share one namespace).

| Record | Prefix | Example |
| --- | --- | --- |
| Topic | `topic-` | `topic-a1-greetings` |
| Dialogue | `dlg-` | `dlg-campus-cafe` |
| Vocabulary pack | `pack-` | `pack-cafe-a2` |
| Vocabulary entry | `voc-` | `voc-coffee` |
| Reading | `read-` | `read-library-card` |
| Listening | `listen-` | `listen-to-the-station` |
| Debate motion | `motion-` | `motion-phones-in-class` |

Question ids are unique inside their piece only. They are not part of the global id set. `q1` may repeat on another piece.

A dialogue lists 2 or 3 roles. Every turn `role` must be one of those names. A listening lists at least one role, and every script line uses one of them. Reading and listening questions need at least 2 options. `answer` is a 0-based integer index into `options`.

`counts.turns` in the index is the number of dialogue turns only. Listening script lines are checked, then dropped.

## Manifests

Each area may include an optional `manifest.json`. Missing manifests are fine.

| Area | Path | `files` entries resolve under |
| --- | --- | --- |
| curriculum | `content/curriculum/manifest.json` | `content/curriculum/` |
| dialogues | `content/dialogues/manifest.json` | `content/dialogues/` |
| vocabulary | `content/vocabulary/manifest.json` | `content/vocabulary/packs/` |
| reading | `content/reading/manifest.json` | `content/reading/` |
| listening | `content/listening/manifest.json` | `content/listening/` |
| debates | `content/debates/manifest.json` | `content/debates/` |

```json
{
  "area": "dialogues",
  "title": "Dialogues",
  "description": "Optional catalog.",
  "files": ["campus-cafe.json"]
}
```

`area` must match the folder. `files` is optional. Each name is a single file in that directory (no `..`). If you list a file, it must exist.

`content/curriculum/` is only `topics.json` plus an optional manifest. `content/debates/` is only `motions.json` plus an optional manifest. Other JSON files there are ignored with a warning.

## Index

`content/index.json` is generated. Do not hand-edit it. Records stay light:

```json
{
  "version": 1,
  "counts": {
    "topics": 0,
    "dialogues": 0,
    "turns": 0,
    "vocabEntries": 0,
    "readings": 0,
    "listenings": 0,
    "debates": 0
  },
  "topics": [{ "id": "", "title": "", "level": "", "domain": "", "themes": [] }],
  "dialogues": [{ "id": "", "title": "", "level": "", "domain": "", "themes": [], "roles": [] }],
  "vocabulary": [{ "id": "", "headword": "", "type": "", "level": "", "theme": "", "packId": "" }],
  "pieces": [{ "id": "", "kind": "reading", "title": "", "level": "", "domain": "", "themes": [] }]
}
```

Readings, listenings, and debates all land in `pieces` (`kind` is `reading`, `listening`, or `debate`). When every count is zero, the file also has a `note` string.

## Add a piece

1. Pick an id with the prefix for that type.
2. Add the JSON file in the path from the table. Dialogue, reading, and listening files are arrays. A vocab file is one pack object. Topics and motions append to the existing array file.
3. Run validation. Fix every `ERROR` line (it names the file, the id, and the problem).
4. Rebuild the index and commit both the new JSON and `content/index.json`.

```
node scripts/validate-content.mjs
node scripts/build-index.mjs
```

Self-test against the tiny fixtures (this does not write the real index):

```
node scripts/validate-content.mjs --root content/fixtures
node scripts/build-index.mjs --root content/fixtures --out /tmp/fixtures-index.json
```

Run the commands from the repository root. The default content directory is still the repo `content/` folder even if the shell is elsewhere. `--root` and `--out` are resolved from the current working directory.

Missing corpus folders warn and exit 0, so the scripts are safe before any lessons land. A file that exists and is invalid JSON, or that breaks the schema, exits 1.

```
WARN content/dialogues: directory not found, skipped
ERROR content/dialogues/cafe.json [dlg-campus-cafe]: item 0: turns must contain at least 8 items (got 3)
counts topics=0 dialogues=1 turns=3 vocabEntries=0 readings=0 listenings=0 debates=0
FAILED 1 error(s)
```

`OK` means exit 0. Counts include every object scanned. The index file is written only when there are no errors.
